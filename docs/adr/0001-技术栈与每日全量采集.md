# 采用 Vite/Vue3 + Go + SQLite，并对中行代销净值做每日全量采集

个人理财收益追踪是单机/自托管 Web：公开净值与用户持仓分离，历史净值只能从采集日起向前积累。选定 Vite + Vue 3 + pnpm 前端、Go 后端、SQLite 落库；采集策略按「每个自然日全量拉取中行全部产品分页」执行，而不是只深采当前有持仓的产品。

**Status:** accepted（采集范围以用户明确要求为准，覆盖 PRD N3 的「仅深采已追踪产品」）

## Considered Options

- 只采集「至少一名用户正在追踪」的产品（PRD N3）：请求更少，但新加仓/调仓换品时没有采集日起的净值序列，后续产品分析也缺全市场样本。
- 每日全量分页扫描并落库：约 191 页、节流后一天几次可接受；库中从启动日起积累全目录净值与上下架痕迹。
- PostgreSQL：并发与运维更强，对「百级用户、千级持仓 + 全目录日更」当前过重。

## Consequences

- `产品代码 + 净值截止日期` 仍是净值业务键；全量抓取不会补回采集开始日之前的历史。
- 添加持仓可先查本地产品/净值库，减少当场扫 191 页导致的超时。
- SQLite 单写者：HTTP 与采集跑在同一 Go 进程、WAL 模式即可；多实例部署需另议。
- 观测表（ADR 0002）与全量策略配套：每天能回答「页面当时仍挂在哪一净值日」。

# 中国银行理财产品净值数据源说明

## 1. 数据源概述

数据来源：

[中国银行——当日代销理财产品净值](https://www.bankofchina.com/sourcedb/srfd6_2024/index.html?utm_source=chatgpt.com)

该页面用于展示中国银行代销理财产品的最新净值信息。

页面中的产品并不全部属于中国银行旗下理财机构，也包括中国银行代销的其他理财机构产品。例如，产品代码 `AF247494G` 对应的产品发行机构为信银理财，中国银行页面同样会展示该产品的净值信息。

该数据源适合用于建立个人理财产品收益追踪工具。

------

## 2. 页面地址结构

数据页面位于固定目录：

```text
https://www.bankofchina.com/sourcedb/srfd6_2024/
```

页面采用静态 HTML 分页方式。

第一页：

```text
index.html
```

后续页面：

```text
index_1.html
index_2.html
index_3.html
...
```

页面编号规律：

```text
index.html       第 1 页
index_1.html     第 2 页
index_2.html     第 3 页
...
```

当前页面共有约 191 页。

分页页面属于同一个产品数据集合的不同分页，并不代表不同日期。

例如：

```text
index.html
index_1.html
index_2.html
```

分别代表产品列表的不同部分，并不能理解为：

```text
今天
昨天
前天
```

------

## 3. 页面数据形式

页面采用 HTML 表格直接展示产品数据。

当前页面包含以下主要字段：

| 字段                     | 含义                           |
| ------------------------ | ------------------------------ |
| 产品代码                 | 理财产品唯一代码               |
| 产品名称                 | 理财产品名称                   |
| 单位净值                 | 产品当前公布的单位净值         |
| 累计净值                 | 产品累计净值                   |
| 每万份基金单位收益       | 部分产品提供该数据             |
| 七日年收益率、净值增长率 | 部分产品提供该数据             |
| 日净值增长率             | 产品最近一次公布的日净值变化   |
| 截止日期                 | 当前这条净值数据对应的净值日期 |

不同产品所使用的数据字段可能存在差异。

例如部分净值型理财产品主要使用：

```text
单位净值
累计净值
日净值增长率
截止日期
```

部分现金管理类产品可能出现：

```text
每万份基金单位收益
七日年收益率
```

因此后续开发时需要按照页面实际字段处理，不应该假定所有产品都会提供全部字段。

------

## 4. 数据的核心含义

页面展示的是：

**各理财产品当前已经公布的最新净值数据。**

这里的“最新”针对每一个产品分别计算。

因此同一页面中，不同产品可能存在不同的“截止日期”。

例如同一时间查看页面时，可能出现：

```text
产品 A
截止日期：2026/09/20

产品 B
截止日期：2026/09/19

产品 C
截止日期：2026/09/18
```

这属于正常情况。

原因是不同理财产品的净值公布时间可能不同。

因此不能简单认为：

```text
页面访问日期 = 产品净值日期
```

应该始终以产品记录中的“截止日期”为准。

## 6. 分页与产品查询

由于全部产品分布在约 191 个分页中，因此指定产品不一定位于第一页。

例如：

```text
index.html
index_1.html
index_2.html
...
index_190.html
```

每个页面包含一部分产品。

首次建立产品追踪时，需要从全部分页中找到目标产品所在页面。

找到产品后，可以记录其当前所在分页，以减少后续查询范围。

需要注意：

产品在页面中的位置并不属于稳定的数据标识。

随着中行产品数据更新，产品所在分页可能发生变化。

因此后续仍需要具备重新搜索全部分页的能力。

------

## 7. 分页与历史数据的关系

这是该数据源最重要的特点之一。

`index.html`、`index_1.html`、`index_2.html` 等页面表示产品列表分页，不表示历史日期。

例如：

```text
index_37.html
```

不能理解为某一天的历史数据页面。

今天访问：

```text
index_37.html
```

和未来某一天访问：

```text
index_37.html
```

页面内容可能发生变化。

因此该网站本身提供的是：

**当前时点各产品最新已公布数据。**

它并不直接按照日期提供完整的历史净值快照。

------

## 8. 历史净值数据的获取方式

如果需要建立某个理财产品的长期收益曲线，仅依靠当前页面无法直接获得完整历史数据。

例如某一天页面显示：

```text
AF247494G
单位净值：1.0562
截止日期：2026/09/18
```

之后中行更新该产品：

```text
AF247494G
单位净值：1.0571
截止日期：2026/09/21
```

原来的：

```text
1.0562
2026/09/18
```

可能仍然对应历史数据，但当前页面主要展示最新数据。

因此，如果需要长期保存历史净值，需要从开始追踪之日起持续保存每天获取到的数据。

形成：

```text
2026/09/18    1.0562
2026/09/21    1.0571
2026/09/22    ...
2026/09/23    ...
```

随着时间积累，就可以形成完整的个人历史净值数据。

------

## 9. “截止日期”的重要性

对于收益追踪工具而言，“截止日期”是非常重要的字段。

例如当前日期为：

```text
2026/09/21
```

但产品数据显示：

```text
截止日期：2026/09/18
单位净值：1.0562
```

这代表：

**目前能够获取到的最新产品净值对应 2026/09/18。**

它不能表示：

```text
2026/09/21 的产品净值就是 1.0562
```

因此应用界面应该明确区分：

```text
当前查询时间
最新净值
净值截止日期
```

这样可以避免把历史净值误认为当天收益。

------

## 10. 与银行 App 展示方式的区别

实际使用中可能出现：

```text
今天没有新的产品净值
```

此时银行 App 仍然可能展示上一条已经公布的数据。

例如：

```text
今天：2026/09/21

最新公布净值：
2026/09/18
1.0562
```

如果直接显示：

```text
当前收益：590 元
```

用户很难判断这个收益究竟对应哪一天。

个人收益追踪工具应该保留数据日期信息，例如：

```text
最新净值：1.0562
净值日期：2026/09/18
距离当前日期：3 天
```

这样用户能够明确知道当前数据的新旧程度。

------

## 11. 数据更新特点

不同产品的净值更新时间可能不同。

因此不能简单按照所有产品统一的交易日判断数据是否已经更新。

对于某一个具体产品，应当比较：

```text
当前日期
```

与：

```text
该产品最新记录的截止日期
```

从而判断该产品目前是否已经产生新的净值数据。

例如：

```text
当前日期：2026/09/21

AF247494G
最新截止日期：2026/09/18
```

可以明确表示：

```text
目前没有获取到 2026/09/19 之后的新净值
```

至于这是因为产品尚未公布、非交易日、节假日还是其他原因，需要结合产品自身的净值公布规律进一步判断。

------

## 12. 数据源使用边界

该数据源适合获取：

- 理财产品代码
- 理财产品名称
- 单位净值
- 累计净值
- 日净值增长率
- 部分产品的每万份收益
- 部分产品的七日年化收益率
- 产品净值截止日期

该数据源不能直接提供：

- 用户个人持仓金额
- 用户持有份额
- 用户购买价格
- 用户实际购买日期
- 用户实际赎回金额
- 用户个人累计收益
- 当天尚未公布的产品净值
- 产品未来净值

因此个人收益需要结合用户自己的持仓信息计算。

------

## 13. 后续收益追踪所需的数据关系

对于净值型理财产品，核心关系可以简化为：

```text
用户持仓信息
        +
产品每日净值
        ↓
个人收益
```

产品数据部分主要来自中国银行公开净值页面。

个人持仓数据需要由用户自行提供。

例如：

```text
产品代码：AF247494G
购买金额：100,000 元
购买净值：1.0500
```

后续获取：

```text
最新净值：1.0562
```

即可根据用户持有份额计算当前对应的资产价值和收益。

------

## 14. 数据采集策略上的关键结论

后续开发时需要遵循以下数据规则：

1. 中国银行该页面属于静态 HTML 数据页面。
2. 页面没有可供本项目直接使用的公开 JSON 接口。
3. 数据通过分页 HTML 页面提供。
4. `index.html` 是第一页，`index_1.html`、`index_2.html` 等属于后续分页。
5. 分页代表产品列表的不同部分，不代表不同日期。
6. 当前页面展示的是各产品已经公布的最新净值。
7. 不同产品的截止日期可能不同。
8. 页面访问日期不能直接作为产品净值日期。
9. 产品历史净值不能通过分页编号直接获得。
10. 如果需要长期历史数据，需要持续保存每次获取到的产品净值。
11. `产品代码 + 净值截止日期` 可以作为识别产品某一天净值记录的重要信息。
12. 对于 `AF247494G`，后续收益追踪应重点关注其单位净值、日净值增长率以及截止日期。

------

## 15. 对后续开发的直接意义

这个数据源已经足以支持个人理财收益追踪工具的数据采集基础。

后续系统可以围绕以下信息展开：

```text
产品
├── 产品代码
├── 产品名称
└── 发行机构

净值
├── 单位净值
├── 累计净值
├── 日净值增长率
└── 净值截止日期

持仓
├── 购买金额
├── 购买日期
├── 购买净值
└── 持有份额

收益
├── 当前资产价值
├── 当日收益
├── 累计收益
└── 累计收益率
```

其中，中国银行公开页面主要负责提供“产品”和“净值”部分的数据，用户自己的持仓信息负责提供“持仓”部分的数据，最终由系统计算个人收益。

对于 `AF247494G`，当前已经确认中国银行公开页面可以作为后续数据采集的重要数据源。后续开发阶段还需要进一步确认该产品发行机构信银理财是否存在公开的历史净值数据源，以解决项目初始历史数据的问题。

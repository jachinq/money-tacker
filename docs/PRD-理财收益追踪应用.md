## 1. 背景与问题

用户会在银行渠道购入净值型理财产品（例如今日购入 1 万元），之后关心的不是「产品页面上最新一条净值是多少」，而是：

- 我这笔持仓今天赚了多少、累计赚了多少；
- 官网当天没有公布新净值（「挂零」）时，应用仍要给出明确的「今日收益」展示，而不是空白或把旧净值误当成今天的收益；
- 同时追踪多只产品；
- 支持多用户各自登录、各自持仓。

中国银行「当日代销理财产品净值」页面（[数据源](https://www.bankofchina.com/sourcedb/srfd6_2024/)）可提供产品代码、名称、单位净值、累计净值、日净值增长率、净值截止日期等公开信息，**不提供**用户持仓金额、份额、买入价。个人收益必须由「用户录入的持仓」+「系统采集的净值」计算得出。

该页面只展示各产品**当前已公布的最新净值**，分页是产品列表分页而非历史日期；历史净值需要从开始追踪之日起由系统自行落库积累。详见关联数据源文档。

## 2. 目标与非目标

### 2.1 产品目标

1. 用户录入**产品代码**和**购入金额**后，系统能绑定公开净值，并持续计算该持仓账户的资产与收益。
2. 每个自然日，应用必须给出该持仓的**当日收益展示**（含 0），即使官网当天未更新净值。
3. 同一用户可同时追踪**多只产品**；同一产品支持**追加买入**与**部分/全部赎回**流水，而不是只能删掉重建。
4. 提供基础**用户体系**，数据按用户隔离。
5. 界面明确区分：查询时间、最新净值、净值截止日期、当日收益对应的净值日，避免把旧净值当成「今天」。

### 2.2 成功标准（MVP）

- 用户用产品代码（如 `AF247494G`）+ 金额完成建仓后，能在列表中看到该产品名称、最新净值、净值日、持仓市值、累计收益、当日收益。
- 同一产品可追加买入、部分赎回；赎回后列表市值按剩余份额计算，累计收益包含已实现部分。
- 官网该产品当日无新净值时，当日收益显示为 **0**（或按「延迟一日」规则显示，见 6.4），且标明净值尚未更新。
- 至少 2 个独立账号互不可见对方持仓与流水。
- 系统每个自然日全量采集中行代销目录并落库（净值快照 + 观测），形成后续曲线与产品分析的数据基础。

### 2.3 非目标（本期不做）

- 真实银行账户授权、银证通、自动扣款或代销下单。
- 完整全市场历史净值回填（中行页面不提供按日历史快照；发行机构历史源待后续调研）。
- 分红再投、申赎费、税费、业绩报酬的精确核算（用户按银行到账**净额**记账）。
- 份额批次 FIFO/指定批次赎回（一期用平均成本）。
- 投顾建议、风险评测、产品推荐。
- 移动端原生 App（MVP 以 Web 为主，后续可再做）。

## 3. 用户与使用场景

### 3.1 角色

| 角色 | 说明 |
| --- | --- |
| 注册用户 | 管理自己的持仓与收益视图 |
| 系统（采集任务） | 定时抓取中行代销净值页，写入已追踪产品的净值记录 |
| 管理员（可选，可后置） | 查看采集任务健康度、失败日志；MVP 可用运维手段代替 |

### 3.2 主场景

**场景 A：今日买入并开始追踪**

用户今天买入某只理财 10,000 元。打开应用，输入产品代码与购入金额（及购入日期，默认为今天）。系统根据购入日可得净值估算份额，之后每日按新净值更新市值与收益。

**场景 B：官网挂零**

某日中行页面上该产品「截止日期」仍为更早一天，当天没有新净值。应用在「今日收益」位置显示 **0**，并提示「净值未更新 / 净值日为 YYYY-MM-DD」。用户不会误以为今天又赚了一笔。

**场景 C：多产品并行**

用户同时持有多只代销理财。首页汇总总市值、总累计收益、总当日收益；可下钻到单只产品的净值与收益明细。

**场景 D：多用户**

用户甲、乙各自注册。甲的持仓与收益对乙不可见。

**场景 E：追加买入**

用户已持有 `AF247494G`，再买入 5,000 元。系统按追加日净值增加份额与成本，总览仍是一只产品一行，详情可看到两笔买入流水。

**场景 F：部分赎回**

用户赎回一部分份额（或按金额折算份额）。系统减少剩余份额，计算该笔已实现收益；未赎回部分继续按最新净值计算市值与未实现收益。超额赎回必须失败。

**场景 G：换仓**

用户赎回产品 A 的部分或全部，再买入产品 B。两只产品各记各的流水；净值来自系统已采集的公共库，不能从中行页推断用户换了什么。

## 4. 核心概念

| 术语 | 定义 |
| --- | --- |
| 产品 | 以**产品代码**为唯一标识的理财产品（如 `AF247494G`）。名称、发行机构来自公开页。 |
| 净值记录 | 某产品在某一**净值截止日期**上的单位净值等字段。业务键：`产品代码 + 净值截止日期`。 |
| 持仓账户 | 某用户对某产品代码的一本账。业务键：`用户 + 产品代码`。总览按账户展示，不按单笔买入拆行。 |
| 流水 | 持仓账户上的一条不可改写资金变动：买入（含首次建仓与追加）或赎回（部分/全部）。份额、剩余成本由流水还原。 |
| 剩余成本 | 尚未赎回份额对应的本金（平均成本法）。 |
| 未实现收益 | 剩余份额 × 最新单位净值 − 剩余成本。 |
| 已实现收益 | 各笔赎回：赎回金额 − 该笔摊销的剩余成本。 |
| 累计收益 | 未实现收益 + 已实现收益。赎回后已赚到的钱仍计入该产品。 |
| 净值日 | 该条净值记录的「截止日期」，不是页面访问日。 |
| 查询日 / 自然日 | 用户打开应用或系统结算时所在的日历日（以约定时区，默认 `Asia/Shanghai`）。 |
| 当日收益 | 针对某个展示日 D：若存在净值日 = D 的新净值，则按相邻净值计算当日盈亏；若官网对 D **挂零（无该日净值）**，则当日收益记为 **0**。 |
| 挂零 | 在自然日 D，公开源尚未提供（或明确不提供）该产品净值日为 D 的记录。应用仍必须展示 D 的当日收益，默认 **0**。 |
| 最新净值 | 系统已保存的、该产品净值日最大的那条单位净值。不等于「今天的净值」。 |

## 5. 范围与分期

### 5.1 MVP（必须交付）

- 注册 / 登录 / 退出（邮箱或用户名 + 密码即可）。
- 添加持仓账户：产品代码 + 购入金额 + 购入日期（默认今天），写入首笔买入流水。
- 同一产品追加买入；按份额或金额部分赎回、全部赎回；超额赎回拒绝。
- 按产品代码在中行分页 HTML 中查找产品；找不到时明确报错，不写流水。
- 每个自然日全量采集中行代销目录：净值快照（`产品代码 + 净值日` 去重）+ 观测记录（每次成功任务每只产品一行）。
- 持仓列表与产品详情：剩余市值、未实现/已实现/累计收益、累计收益率、当日收益、净值日、数据新鲜度；详情展示流水。
- 多产品；用户级数据隔离。
- 挂零日当日收益为 0，且 UI 标明未更新。申赎本身不记入当日收益。

### 5.2 后续迭代（明确延后）

- 发行机构历史净值补全（如信银理财公开源），用于买入日早于「开始采集日」的情况。
- 现金管理类（每万份收益）单独算法；FIFO 指定批次赎回。
- 收益曲线图、导出、消息推送（净值更新 / 连续挂零提醒）。
- OAuth、手机号登录、RBAC 管理后台。
- 除中行代销页以外的数据源。

### 6.4 净值采集与「挂零」

| ID | 需求 | 优先级 |
| --- | --- | --- |
| N1 | 采集来源仅为中行静态 HTML 分页，无官方 JSON API 可用。 | P0 |
| N2 | 调度：每个自然日至少采集 1 次；建议交易日白天多次（例如 10:00 / 16:00 / 21:00），以覆盖晚公布。 | P0 |
| N3 | 每个自然日对中行代销目录做全量分页扫描并落库；净值按 `产品代码 + 净值截止日期` 去重，同时写入观测（即使净值日未变）。 | P0 |
| N4 | 写入净值记录时以 `产品代码 + 净值截止日期` 去重；同一净值日重复抓取则更新可变字段。 | P0 |
| N5 | **页面访问日 ≠ 净值日**。禁止用抓取日期冒充截止日期。 | P0 |
| N6 | 自然日 D 结束时（或用户查看「今天」时），若库中不存在净值日 = D 的记录，则视为挂零。 | P0 |
| N7 | 挂零时：**展示日 D 的当日收益 = 0**。市值、累计收益仍按最新已公布净值计算。 | P0 |
| N8 | 允许实现「展示延迟一日」：用户看到的「今日」对应上一自然日的结算结果。无论是否延迟，**每个展示日都必须有当日收益数字（可为 0）**，不得留空。 | P0 |
| N9 | UI 必须同时展示：最新单位净值、净值截止日期、相对今天的间隔天数。 | P0 |

**推荐默认策略（MVP）**

- 采用 **「日历日展示 + 挂零记 0」**，不采用把旧涨跌重复算进今天。
- 「延迟一日」作为可配置项：若运营希望与银行 App 公布节奏对齐，可将「今日收益」定义为「最近一个已完成结算日」的收益，未完成日仍显示 0 并带「待更新」。

**挂零示例**

```text
今天：2026-09-21
AF247494G 最新截止日期：2026-09-18，单位净值 1.0562

当日收益（2026-09-21）：0
累计收益：仍按最新已公布净值相对剩余成本（加已实现）计算
提示：净值未更新，净值日 2026-09-18，已间隔 3 天
```

当 2026-09-21 的净值随后公布（截止日期变为 2026-09-21）时，系统写入新净值记录，并将 2026-09-21 的当日收益从 0 重算为真实涨跌。允许「先 0 后修正」，与「延迟一天再显示」两种体验均满足「必须显示」的底线。

### 6.5 收益计算

约定：净值型产品使用**单位净值**。持仓账户的份额与成本由**未作废流水**按发生日、写入顺序还原。

```text
买入：剩余份额 += 金额/净值；剩余成本 += 金额
赎回：摊销成本 = 剩余成本 × (赎回份额/赎回前份额)
      已实现 += 赎回金额 - 摊销成本
      剩余份额 -= 赎回份额；剩余成本 -= 摊销成本

最新市值             = 剩余份额 × 最新单位净值
未实现收益           = 最新市值 - 剩余成本
累计收益             = 未实现 + 已实现
                     = 最新市值 + 累计赎回金额 - 累计买入金额
累计收益率           = 累计收益 / 累计买入金额   （旁注：按累计申购本金）
持仓收益率           = 未实现 / 剩余成本         （剩余份额为 0 则不展示或显示 —）

对展示日 D（发生日 < D 的流水决定 D 日开盘份额 shares_sod）：
  若 D 挂零（无净值日 = D）：
    当日收益 = 0
    （当日申赎不产生当日收益；市值仍按最新已公布净值）
  若存在 NAV_D：
    持有部分：若存在 NAV_prev，则 shares_sod × (NAV_D - NAV_prev)；否则 0
    当日买入：该日买入份额 × (NAV_D - 该笔买入净值)
    当日赎回：赎回份额已含在 shares_sod 中，不再另加减
    当日收益 = 持有部分 + 当日买入
```

约定：申赎按发生日所用净值估值，无日内分时。赎回发生在净值日 D 且赎回净值 = NAV_D 时，被赎回份额仍享受 D 日涨跌（已计入当日收益）。

| ID | 需求 | 优先级 |
| --- | --- | --- |
| R1 | 按上式计算；金额展示保留 2 位小数，收益率百分比保留 2 位。 | P0 |
| R2 | 多账户按用户求和得到总市值、总累计收益、总当日收益（累计含已实现）。 | P0 |
| R3 | 现金管理类字段（每万份收益、七日年化）MVP 只展示原始值，不纳入当日收益公式；若用户追踪的是净值型（如 AF247494G）则走单位净值公式。 | P1 |
| R4 | 不把「日净值增长率」当作唯一计算依据；以单位净值差额为准，增长率为辅助展示。 | P0 |
| R5 | 挂零日当日收益必须为 0；申赎现金流不记入当日收益。 | P0 |
| R6 | 总览「累计收益」在部分赎回后不得把已实现收益丢弃。 | P0 |

| 总览 | 总市值、总累计收益（含已实现）、总当日收益；当日数据状态（已更新 / 挂零） |
| 持仓列表 | 每只产品一本账户：名称、代码、剩余成本、市值、未实现/累计收益、当日收益、净值日 |
| 添加 / 追加 | 代码（追加时已定）、金额、日期、可选手动净值 |
| 赎回 | 份额或金额或「全部赎回」、日期、可选手动净值 |
| 产品详情 | 流水列表、已保存的净值序列、按日收益（含挂零 0）、新鲜度 |
| 账户 | 退出、改密 |

文案约束：禁止只显示「当前收益 590 元」而不给净值日。银行 App 可能把旧数据当今天展示，本产品刻意相反。

## 8. 数据源约束（写入研发合同）

摘自关联说明，作为本 PRD 的硬约束：

1. 页面为静态 HTML 分页：`index.html` 为第 1 页，`index_N.html` 为第 N+1 页；分页不是日期。
2. 无项目可直接使用的公开 JSON 接口。
3. 展示的是各产品**已公布的最新净值**；不同产品截止日期可以不同。

5. `AF247494G`（信银理财安盈象固收稳利一个月持有期 60 号）作为首个验收产品；中行是代销展示方。
6. 公开源不提供个人持仓与当天未公布净值。

## 10. 验收用例

1. **建仓**：用户录入 `AF247494G` + `10000`，列表出现该产品中文名，份额与市值合理。
2. **多产品**：同一用户再添加另一中行列表内产品，总览为两账户之和。
3. **多用户**：用户 B 登录看不到用户 A 的持仓与流水。
4. **挂零**：构造「今天无该产品新截止日期」的数据，今日收益为 `0.00`，并显示旧净值日。
5. **净值更新**：写入今天的新单位净值后，今日收益变为开盘份额 × 净值差（加当日本笔买入相对买入净值的差），累计收益同步变化。
6. **找不到代码**：输入不存在代码，不创建账户与流水，有明确错误。
7. **追加**：同一产品再买入 5000，份额与剩余成本增加，列表仍一行。
8. **部分赎回**：赎回部分份额后市值下降，已实现收益入账，累计收益 = 未实现 + 已实现。
9. **超额赎回**：赎回份额大于剩余时失败，账户不变。
10. **清仓**：全部赎回后默认列表不再展示该行（或标已清仓），详情仍能看到流水与已实现收益。

2. ~~同一产品多笔买入：列表默认按产品聚合还是按笔？~~ **已定：总览/列表按持仓账户（产品）一行，详情展示流水。**

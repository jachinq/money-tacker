# 当日收益的展示日取「不晚于自然日减一的最近已有净值日」，按产品分别计算

ADR 0003 只锁定了「不看打开应用的那个自然日」。本决策锁定算法：不做日历减一、不维护交易日历。产品 A 与产品 B 的展示日可以不同，因为中行页上各产品截止日期本就不同。

这与 PRD 原稿「挂零则总览当日收益 = 0」不同：周末或净值晚公布时，总览仍显示上一笔已完成结算日的盈亏，并用新鲜度标明「自然日−1 尚无净值」。无任何不晚于昨天的净值时，当日收益才是 0。

**Status:** accepted

## Considered Options

- 日历减一：字面 T-1；周末和节假日总览经常为 0。
- 不晚于昨天的最近已有净值日：对齐银行「昨日收益」习惯，无需交易日历。
- 滚动到含今天的最新净值日：会把当天已公布净值算进「当日」，违反延迟一日。

## Consequences

- 总览加总可能把不同净值日的「当日收益」加在一起；是否接受由后续产品确认。
- `DISPLAY_LAG_DAYS=1` 表示上界是昨天，不是「永远展示日历昨天那一格」。
- 按日明细若仍对缺日填 0，会与总览headline 口径不同，必须在 UI 上拆开。

# 总览与当日收益按全局展示日（自然日减延迟），默认延迟一日

PRD 曾建议 MVP 用「日历日当天 + 挂零记 0」，技术设计默认 `DISPLAY_LAG_DAYS=0`。产品决定与银行理财常见口径对齐：收益按 T-1 结算，不做用户级开关。展示日全局延迟一日；未完成结算的日子仍显示 0 并标明待更新。精确算法（日历减一、跳过周末、还是落到最近已公布净值日）另轮确认，但「看的是昨天这档，不是打开应用的那个自然日」已定。

**Status:** accepted（算法细节见 ADR 0004）

## Considered Options

- 日历日当天展示，挂零记 0，净值稍后公布再从 0 修正：信息最新，但和银行 App「昨日收益」习惯不一致。
- 全局延迟一日：与常见 T-1 净值公布节奏一致；周末或连续挂零时「昨天」可能仍无净值，当日收益为 0。
- 用户级开关：同一家庭两个账号口径分裂，总览无法解释。

## Consequences

- UI 文案必须同时给出展示日与净值日，避免「今日收益」被读成自然日当天。
- `DISPLAY_LAG_DAYS` 默认 1，表示展示日上界为自然日减一，不是把日历昨天强行当作结算日。
- 挂零改为新鲜度，不再把总览当日收益改写成 0（ADR 0004）。
